本文记录如何使用 **Cloudflare AI Gateway + Custom Provider + ZenMux** 搭建一个统一的 AI API 网关。

---

## 一、最终实现流程

```text
Codex / Junie / Grok CLI / OpenAI SDK
          │
          ▼
https://ai.ichochy.com
          │
          ▼
Cloudflare AI Gateway
          │
    Custom Provider
          │
          ▼
       ZenMux
    ┌─────┼─────┐
    ▼     ▼     ▼
  GPT  Claude  GLM
    │           │
DeepSeek      Grok
```

客户端只需访问自己的域名：`https://ai.ichochy.com`。

---

## 二、需要配置的内容

整个配置主要分为 5 步：

1. 创建 AI Gateway
2. 配置自定义域名
3. 创建 Gateway 身份验证令牌
4. 创建 ZenMux Custom Provider
5. 添加 ZenMux Provider API Key

最终配置一览：

| 配置项            | 示例值                       |
|-------------------|------------------------------|
| Gateway           | `zenmux`                     |
| Domain            | `ai.ichochy.com`             |
| Custom Provider   | `ZenMux`                     |
| Provider Slug     | `zenmux`                     |
| Base URL          | `https://zenmux.ai/api`      |
| Gateway Token     | Cloudflare Gateway Token     |
| Provider Key      | ZenMux API Key               |

## 三、准备工作

需要准备：

- 一个 Cloudflare 账号
- 一个已托管到 Cloudflare 的域名
- 一个 ZenMux 账号
- 一个 ZenMux API Key

本文使用示例：

```text
Cloudflare Gateway：zenmux
自定义域名：ai.ichochy.com
ZenMux Base URL：https://zenmux.ai/api
模型示例：z-ai/glm-5.3-flash
```

---

## 四、创建 Cloudflare AI Gateway

登录 Cloudflare Dashboard：

```text
AI → AI Gateway → Create Gateway
```

Gateway 名称填写：

```text
zenmux
```

创建完成后，该 Gateway 将成为整个 AI API 的入口。

---

## 五、配置自定义域名

进入 Gateway 页面：

```text
AI Gateway → zenmux → Custom Domains
```

添加域名：

```text
ai.ichochy.com
```

完成 DNS 和域名验证后，即可通过：

```text
https://ai.ichochy.com
```

访问 AI Gateway。

使用自定义域名后，客户端无需暴露 Cloudflare Account ID 或 API Token，URL 更加简洁。

---

## 六、创建 Gateway Token

在 AI Gateway 中创建 **Authentication Token**（即 `CLOUDFLARE_API_TOKEN`）。

该 Token 用于客户端访问 AI Gateway：

```bash
export CLOUDFLARE_API_TOKEN="你的 AI Gateway Authentication Token"
```

---

## 七、创建 ZenMux Custom Provider

进入：

```text
AI Gateway → Custom Providers → Add Custom Provider
```

填写信息：

| 字段           | 值                        |
|----------------|---------------------------|
| Provider Name  | ZenMux                    |
| Provider Object | zenmux                   |
| Base URL       | `https://zenmux.ai/api`   |
| Status         | Enable                    |

保存后即可。

### 为什么 Base URL 是 `/api` 而不是 `/api/v1`？

ZenMux 的 OpenAI 兼容接口实际地址为：

```text
https://zenmux.ai/api/v1
```

但 Custom Provider 的 Base URL **不要**写成 `/api/v1`。

原因：Cloudflare 会把客户端请求的路径直接追加到 Base URL 后面。

客户端请求示例：

```text
/custom-zenmux/v1/chat/completions
```

Cloudflare 实际转发为：

```text
https://zenmux.ai/api + /v1/chat/completions
→ https://zenmux.ai/api/v1/chat/completions
```

如果 Base URL 已经包含 `/v1`，就会变成 `/api/v1/v1/...`，导致 404。

**正确配置：**

```text
Base URL = https://zenmux.ai/api
```

Slug `zenmux` 也很重要，因为客户端后续使用的路径前缀是：

```text
/custom-zenmux/
```

（`custom-` 是 Cloudflare Custom Provider 的固定前缀）

---

## 八、添加 ZenMux Provider Key

Custom Provider 创建完成后，需要告诉 Cloudflare 调用 ZenMux 时使用哪个 API Key。

进入：

```text
AI Gateway → Provider Keys → Add API Key
```

选择 Provider 为 `ZenMux`，填入你的 ZenMux API Key（`sk-xxxxxxxx`），保存。

---

## 九、两套 Key 的关系

系统中存在两套完全不同的 Key：

| Key              | 用途                         | 流向                     |
|------------------|------------------------------|--------------------------|
| `CLOUDFLARE_API_TOKEN`   | 客户端 → Cloudflare Gateway  | 客户端必须携带           |
| `ZENMUX_API_KEY` | Cloudflare → ZenMux          | 保存在 Cloudflare 侧     |

```text
Client ──(CLOUDFLARE_API_TOKEN)──► Cloudflare AI Gateway
                              │
                              │ (BYOK: Provider Key)
                              ▼
                           ZenMux
```

客户端**不需要**保存 ZenMux API Key。

## 十、先直接测试 ZenMux

在接入 Cloudflare 之前，建议先确认 ZenMux 本身可用：

```bash
export ZENMUX_API_KEY="你的 ZenMux API Key"

curl https://zenmux.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $ZENMUX_API_KEY" \
  -H "Content-Type: application/json" \
  --json '{
    "model": "z-ai/glm-5.3-flash",
    "messages": [
      {"role": "user", "content": "Hello"}
    ]
  }'
```

返回正常模型响应即表示 ZenMux 配置正确。

## 十一、通过 Cloudflare 调用 ZenMux

完整链路测试：

```bash
curl https://ai.ichochy.com/custom-zenmux/v1/chat/completions \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  -H "Content-Type: application/json" \
  --json '{
    "model": "z-ai/glm-5.3-flash",
    "messages": [
      {"role": "user", "content": "你好，请用一句话介绍自己。"}
    ]
  }'
```

**关键 Header：**

```http
Authorization: Bearer $CLOUDFLARE_API_TOKEN
```

注意：**不要**使用 `Authorization: Bearer $ZENMUX_API_KEY`，因为 ZenMux Key 已经保存在 Cloudflare Provider Keys 中。

### 请求完整过程

1. 客户端请求 `https://ai.ichochy.com/custom-zenmux/v1/chat/completions`
2. Cloudflare 校验 `Authorization`
3. 识别路径中的 `custom-zenmux`，匹配到 Custom Provider（Slug: `zenmux`）
4. 读取对应的 Provider Key
5. 转发到 `https://zenmux.ai/api/v1/chat/completions`

## 十三、常见问题排查

### 1. 返回 `{"code": 2009, "message": "Unauthorized"}`

- 检查 `CLOUDFLARE_API_TOKEN` 是否为空：`echo ${#CLOUDFLARE_API_TOKEN}`
- 确认 Header 使用的是 `Authorization`，而不是把 ZenMux Key 放进去

### 2. 上游返回 401 Unauthorized

检查 Cloudflare 的 Provider Keys 中，ZenMux 的 API Key 是否正确。可先直连 ZenMux 测试。

### 3. 返回 404

检查 Custom Provider 的 Base URL 是否为：

```text
https://zenmux.ai/api
```

**不要**写成 `https://zenmux.ai/api/v1` 否则会出现路径重复。
