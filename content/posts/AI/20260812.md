OpenAI 的 **Codex CLI** 是一款运行在本地终端的开源 AI 编程智能体，能读写代码、执行命令。默认只能使用官方 OpenAI 模型，通过 **[ZenMux](https://mleo.site/api)**（大模型聚合平台）可以接入更多模型，并支持多配置档案（Profiles）灵活切换。


---

### 一、为什么选择 ZenMux + Codex CLI？

- 完全兼容 OpenAI 协议
- 支持 GPT、Claude、DeepSeek 等多种模型
- 配置一次，CLI 与 Codex App 共用
- 支持启动时用 `-m` / `--model` 临时换模型
- 通过 Profiles `codex -p coding`，快速切换「日常编码 / 深度推理 / 只读分析」等场景


---

### 二、安装 Codex CLI

```bash
# 推荐
curl -fsSL https://chatgpt.com/codex/install.sh | sh

# 或 npm
npm install -g @openai/codex
```

验证安装：

```bash
## 查看版本
codex --version

# 检查
codex doctor   

# 更新
codex update    
```

---

### 三、获取并配置 ZenMux API Key

1. 登录 [ZenMux 控制台](https://mleo.site/api) 创建 API Key（格式通常为 `sk-ai-v1-xxx`）
2. 写入 shell 配置文件（`~/.zshrc` 或 `~/.bashrc`）：

```bash
export ZENMUX_API_KEY="sk-ai-v1-xxx"   # 替换为你的真实 Key
```

生效：

```bash
source ~/.zshrc   # 或 source ~/.bashrc
```

---

### 四、主配置文件

创建或编辑 `~/.codex/config.toml`：

```toml
# ==============================
# Codex CLI + ZenMux 主配置
# ==============================

model_provider = "zenmux"
model = "gpt-5.3-codex"                   # 默认模型
approval_policy = "on-request"            # 需要确认再执行
sandbox_mode = "workspace-write"          # 允许写当前工作区

[model_providers.zenmux]
name = "ZenMux"
base_url = "https://zenmux.ai/api/v1"
env_key = "ZENMUX_API_KEY"
wire_api = "responses"                    # 推荐

[features.multi_agent_v2]
tool_namespace = "agents"
```

### 五、Profiles 完整模板（推荐）

新版本 Codex 使用**独立文件**作为 Profile（`~/.codex/名称.config.toml`），通过 `-p` 切换。

#### 1. 日常编码（推荐默认）

**文件**：`~/.codex/coding.config.toml`

```toml
model = "gpt-5.3-codex"
approval_policy = "on-request"
sandbox_mode = "workspace-write"
model_reasoning_effort = "medium"
```

#### 2. 深度推理

**文件**：`~/.codex/deep.config.toml`

```toml
model = "gpt-5.3-codex"
approval_policy = "on-request"
sandbox_mode = "workspace-write"
model_reasoning_effort = "high"
```

#### 3. 轻量快速

**文件**：`~/.codex/lite.config.toml`

```toml
model = "gpt-5.3-codex"
approval_policy = "on-request"
sandbox_mode = "workspace-write"
model_reasoning_effort = "low"
```

#### 4. 只读分析（安全）

**文件**：`~/.codex/readonly.config.toml`

```toml
model = "gpt-5.3-codex"
approval_policy = "on-request"
sandbox_mode = "read-only"
model_reasoning_effort = "medium"
```

#### 5. 全自动模式（慎用）

**文件**：`~/.codex/yolo.config.toml`

```toml
model = "gpt-5.3-codex"
approval_policy = "never"
sandbox_mode = "workspace-write"
model_reasoning_effort = "medium"
```

#### 6. Claude 模型

**文件**：`~/.codex/claude.config.toml`

```toml
model = "anthropic/claude-sonnet-5"      # 按 ZenMux 实际可用模型调整
approval_policy = "on-request"
sandbox_mode = "workspace-write"
model_reasoning_effort = "medium"
```

#### 7. 高安全审查

**文件**：`~/.codex/review.config.toml`

```toml
model = "gpt-5.3-codex"
approval_policy = "untrusted"
sandbox_mode = "read-only"
model_reasoning_effort = "high"
```

### 七、使用方式

#### 1. 按 Profile 启动

| 场景           | 启动命令              |
|----------------|-----------------------|
| 日常编码（推荐）| `codex -p coding`     |
| 深度推理       | `codex -p deep`       |
| 轻量快速       | `codex -p lite`       |
| 只读分析       | `codex -p readonly`   |
| 全自动（慎用） | `codex -p yolo`       |
| Claude 模型    | `codex -p claude`     |
| 高安全审查     | `codex -p review`     |
| 使用主配置默认 | `codex`               |

#### 2. 用 `-m` / `--model` 临时换模型

启动时直接指定模型，优先级高于 Profile 和主配置：

```bash
# 基础用法
codex -m gpt-5.5
codex --model gpt-5.5

# 结合 Profile 使用（推荐）
codex -p coding -m gpt-5.5
codex -p deep -m anthropic/claude-sonnet-5
codex -p lite -m gpt-5.3-codex

# 完整示例
codex -p coding -m openai/gpt-5.3-codex
codex -p review -m anthropic/claude-sonnet-5
```

**常用模型示例（以 ZenMux 实际支持为准）：**

```bash
# GPT 系列（推荐原厂名称）
codex -p coding -m gpt-5.3-codex
codex -p coding -m gpt-5.5

# Claude 系列
codex -p coding -m anthropic/claude-sonnet-5
codex -p coding -m anthropic/claude-opus-5

# 其他模型
codex -p coding -m deepseek/deepseek-v4-flash
```

> 提示：`-m` 只影响当前这次启动，不会修改配置文件。想长期更换默认模型，请修改对应 Profile 或主 `config.toml` 中的 `model` 字段。

### 八、配置优先级（从高到低）

1. 命令行参数（`-m` / `--model`、`-c` 等）← **最高**
2. 项目级 `.codex/config.toml`
3. Profile 文件（`~/.codex/名称.config.toml`）
4. 用户主配置 `~/.codex/config.toml`
5. 内置默认值

因此：

```bash
codex -p coding -m gpt-5.5
```

最终使用的是 `gpt-5.5`，而不是 Profile 里写的模型。

### 九、常见问题

**1. API Key 无效？**  
确认已正确设置 `ZENMUX_API_KEY` 并执行了 `source`，同时检查控制台密钥是否有效、是否有余额。

**2. 模型调用失败？**  
以 ZenMux 控制台实际支持的模型名为准。GPT 系列推荐直接使用原厂名称（如 `gpt-5.3-codex`）。

**3. `-m` 换模型不生效？**  
确认模型名称拼写正确，且该模型在 ZenMux 上可用。可先不加 Profile 测试：`codex -m 模型名`。

**4. Profile 不生效？**  
确认文件名为 `名称.config.toml`，并使用 `codex -p 名称` 启动。重启终端后再试。

**5. 想同时支持 Codex App？**  
CLI 与 App 共用 `~/.codex/config.toml`，配置一次即可两端使用。App 已运行时请重启一次。

---

### 十、总结

1. 安装 Codex CLI  
2. 设置 `ZENMUX_API_KEY`  
3. 写好主配置 `config.toml`  
4. 创建多个 Profile 文件  
5. 日常用 `codex -p xxx` 启动  
6. 需要临时换模型时加 `-m 模型名`

完成以上步骤后，你就能在终端中稳定使用 ZenMux 提供的多模型能力，并根据任务类型和模型需求灵活切换。
