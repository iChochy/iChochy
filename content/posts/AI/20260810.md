最近一直在用 xAI 的 **Grok Build** 做编码代理。它是一个跑在终端里的强大 coding agent，支持交互式 TUI、无头模式和 ACP 协议，能直接读代码库、改文件、跑命令、管理子代理，体验很流畅。

但默认情况下它主要走 xAI 自家模型。我想更灵活一点：既能用 Grok，也能随时切到 Claude、Gemini、DeepSeek、Qwen 等其他模型。于是就把 **[ZenMux 官网](https://mleo.site/api)** 接了进来。

[ZenMux 官网](https://mleo.site/api) 是一个企业级大模型聚合平台，一个 API Key 就能调用全球主流模型，支持 OpenAI 和 Anthropic 双协议，智能路由，还有质量保障机制。官方文档和模型列表都很清晰。

下面分享一下我是怎么把 Grok Build 对接 ZenMux 的。

## 1. 准备 ZenMux API Key

去 [ZenMux 官网](https://mleo.site/api) 注册登录（支持邮箱、GitHub、Google）。

推荐两种方式：

- **Builder Plan（订阅制）**：固定月费，适合个人开发和学习，性价比高。
- **Pay As You Go（按量付费）**：按实际用量计费，适合生产环境，无 rate limit。

创建对应的 API Key 后保存好（格式一般是 `sk-...`）。

## 2. 安装 Grok Build

```bash
# macOS / Linux
curl -fsSL https://x.ai/cli/install.sh | bash

# Windows PowerShell
irm https://x.ai/cli/install.ps1 | iex
```

安装完验证一下：

```bash
grok --version
```

## 3. 配置自定义模型（核心步骤）

Grok Build 支持通过用户配置文件添加任意自定义模型。编辑：

```bash
~/.grok/config.toml
```

（Windows 下是 `%USERPROFILE%\.grok\config.toml`）

添加类似下面的内容：

```toml
[models]
default = "zenmux-grok"          # 默认使用这个模型

[model.zenmux-grok]
model = "x-ai/grok-4.5"          # ZenMux 上的模型 slug，可换成其他
base_url = "https://zenmux.ai/api/v1"
name = "Grok 4.5 via ZenMux"
description = "通过 ZenMux 调用 Grok"
env_key = "ZENMUX_API_KEY"       # 环境变量名
api_backend = "chat_completions" # 或 "responses"
context_window = 256000
```

你还可以多加几个模型方便切换，比如：

```toml
[model.zenmux-claude]
model = "anthropic/claude-sonnet-4.5"
base_url = "https://zenmux.ai/api/v1"
name = "Claude Sonnet via ZenMux"
env_key = "ZENMUX_API_KEY"
api_backend = "chat_completions"

[model.DeepSeek]
model = "deepseek/deepseek-v4-flash"
base_url = "https://zenmux.ai/api/v1"
name = "DeepSeek V4 Flash"
description = "via ZenMux"
env_key = "ZENMUX_API_KEY"

```

模型 slug 可以在 ZenMux 的 Models 页面直接查看。

## 4. 设置环境变量

在 `~/.zshrc` 或 `~/.bashrc` 里加上：

```bash
export ZENMUX_API_KEY="sk-你的密钥"
```

然后 `source ~/.zshrc` 让它生效。

## 5. 启动并使用

进入项目目录：

```bash
cd /home/iChochy/Code/      # 进入项目目录
grok                        # 启动 grok
```

在 TUI 里按 `Ctrl+M` 打开模型选择器，或者用 `/model zenmux-grok` 切换。

无头模式也可以直接指定：

```bash
grok -p "解释这个代码库的结构" -m zenmux-grok
```

用 `grok inspect` 可以确认当前配置是否被正确加载。

## 使用体验与建议

对接后最大的好处是**模型自由**：同一个 Grok Build 界面，随时切换不同提供商的模型，不用换工具。  
日常编码我常用 Grok 或 Claude Sonnet，复杂推理就切到更强的模型，成本也能通过 ZenMux 的订阅或按量计费灵活控制。

注意几点：

- 确保 `base_url` 带 `/v1`（OpenAI 兼容协议）。
- 如果某个模型需要 Anthropic 协议，可以把 `base_url` 改成 `https://zenmux.ai/api/anthropic`，并设置 `api_backend = "messages"`。
- 生产环境建议用 Pay As You Go Key，订阅 Key 更适合个人学习。

## 总结

Grok Build 本身已经很强，再加上 ZenMux 的模型聚合能力，编码代理的选择空间一下子就打开了。配置其实很简单，改一下 `config.toml` 和环境变量就能用。

如果你也在用 Grok Build，不妨试试对接 ZenMux。有问题或者更好的玩法，欢迎交流。
